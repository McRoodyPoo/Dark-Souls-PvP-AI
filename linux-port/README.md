# ptde-pvp-bot

A Linux-native Dark Souls: Prepare to Die Edition PvP bot, ported to Python and extended from
[metal-crow/Dark-Souls-PvP-AI](https://github.com/metal-crow/Dark-Souls-PvP-AI)
(GPL v2, so this port is GPL v2 too: see `LICENSE` and `NOTICE.md`). This folder lives in a
fork of that repository: metal-crow's original C/C# project is the rest of this repo (`../`),
with its own `LICENSE.md`.

It reads game state from memory (read-only), decides, and drives a virtual
controller. It does not inject code, does not write to game memory, and does not need Cheat Engine.

> violate the game's or platform's terms of service and may get your account restricted. Other

> (see `LICENSE`).

## Requirements

- Linux with `/dev/uinput` writable by your user (virtual gamepad), and a kernel that allows
  same-user reads of `/proc/<pid>/mem` (Wine processes allow this under `ptrace_scope=1`).
- Steam + Proton running Dark Souls: Prepare to Die Edition (the Steamworks build).
- Python 3.10+ (developed on 3.14) in a venv with `numpy`, `evdev` and `Pillow`.
- Optional, used by some features: `bluetoothctl` (reconnecting a Bluetooth controller behind
  the virtual pad), KDE Plasma's `spectacle` (HUD screen checks, freeze screenshots) and
  `qdbus6`/`journalctl` (window-focus detection). Without them those features degrade or turn off.

## Quick start

```bash
python3 -m venv .venv && .venv/bin/pip install numpy evdev pillow
.venv/bin/python tests/test_brain.py && .venv/bin/python tests/test_handoff.py   # no game needed
.venv/bin/python scripts/probe.py --watch          # in a duel: check the memory reads
.venv/bin/python scripts/run_bot.py --dry-run      # print decisions only
.venv/bin/python scripts/run_bot.py                # L3+R3 hands control to the bot
```

`scripts/run_bot.py` flags: `--dry-run` (print decisions, press nothing), `--bot-only` (no
handoff), `--start-as-bot`, `--hz` (decision rate, default 120), `--red-sign` (keep a Red Sign
Soapstone sign down while idle at home), `--no-record`, `--no-greet`, `--sign-down`,
`--no-reload`, `--trinket-selected`, `--allow-r1` (pokes and R1 punishes instead of the default
backstab-only build), `--no-attack-net`, `--no-defense-net`.

`scripts/probe.py` flags: `--watch`, `--pad`, `--calibrate-steering`.

The bot's behaviour is specified in [`RULES.md`](RULES.md): every rule there is enforced by a
test in `tests/test_brain.py` or `tests/test_handoff.py`.

Fight recordings (`recordings/`) and per-opponent records (`records/`) are written at runtime and
are git-ignored; they contain other players' Steam names and IDs, so don't publish them.

## What replaces what

| metal-crow (Windows)                         | here (Linux / Proton)                                   | status |
|----------------------------------------------|---------------------------------------------------------|--------|
| `ReadProcessMemory` + `FindPointerAddr`      | `ptde_ai/memory.py`: `/proc/<pid>/mem`, same chain semantics | done, tested off-game |
| pointer tables in `CharacterStruct.h`        | `ptde_ai/offsets.py` (all Enemy/Player/camera chains)   | ported, **unverified in-game** |
| `ReadPlayer` (raw reads)                     | `ptde_ai/state.py`: snapshot per tick, re-resolved every tick | done |
| virtual controller driver (DirectInput)      | `ptde_ai/gamepad.py`: uinput virtual Xbox 360 pad       | done, kernel sees it |
| Cheat Engine "lock camera rotation" + `OolicelMap` flag | `ptde_ai/steer.py`: camera-relative steering from live yaw | done, needs one in-game calibration |
| AIDecisions / AIMethods / MindRoutines / SubRoutines | `ptde_ai/brain.py` (single-threaded)            | ported, offline-tested |
| CharacterStruct.c subanimation logic         | `ptde_ai/character.py`                                  | ported, offline-tested |
| Memory.c rolling histories                   | `ptde_ai/history.py`                                    | ported |
| AnimationMappings.c / WeaponData.c tables    | `ptde_ai/tables.py`, generated by `tools/convert_tables.py` | converted, entry counts match the C |
| FANN nets (`Neural Nets/*.net`)              | `ptde_ai/nets.py` numpy MLPs, retrained by `tools/train_nets.py` | retrained (see below) |
| main loop (`Source.c`)                       | `scripts/run_bot.py` (`--dry-run` to watch decisions only) | written, needs the game |
| auto red-sign loop (`Handler.c`)             | `ptde_ai/redsign.py`, `ptde_ai/escape.py`, `ptde_ai/focus.py` | verified live |

## Bugs found while porting (all fixed in the port)

- **The shipped neural nets were wrong.** `Attack_dark_souls_ai.net` and
  `Defense_dark_souls_ai.net` are byte-identical and take 5 inputs; the code feeds
  8 and 177. FANN reads only the first 5, so both "brains" were the same mismatched net.
  Retrained from his recordings with scaling saved alongside the weights:
  backstab predictor 87% on held-out data (vs 57% for always guessing the majority);
  attack net 100% on held-out data, but that's only 29 labelled samples, so treat it as weakly validated.
- **The attack training file was misaligned.** 6 rows have two inputs glued together with no
  label, which shifts every later sample if the file is read as a stream (FANN's reader does that).
- **Instinct attacks didn't fire on their own.** "You're in backstab position" only ran if the attack
  net also happened to want an attack.
- **Attacks first seen mid-swing were never dodged.** The timer-resync wait never expired.
- **Distance used absolute coordinates** (`|x1| - |x2|`), wrong whenever the characters straddle 0.
- **Dodge and attack history shared one id space** (StandardRoll == MoveUp == 1), so walking forward
  counted as "just rolled" and changed the next roll's direction.
- **Omnistep ended before its stick input** (his "TODO kind of not working").
- **Pivot backstab never ended**, dead angle logged itself as ghost hit, enemy stamina estimate used the
  current animation for every past attack, and the stamina table had no default (undefined behavior in C).
- **Two threads raced on the same "attack choice" variable.** Now it's one deterministic loop: a tick
  takes about 0.06 ms including both nets.

Tests: `python tests/test_brain.py` (simulated duel situations, no game needed).

## Weak points in the original and the fix for each

1. **Camera must be frozen.** `angleToJoystick` assumes a fixed camera yaw, hence the
   CE script that NOPs every `movss [ebx+144]` write, plus a compile flag per map.
   If the lock slips, every roll and approach goes the wrong way. *Fix:* read the
   camera yaw each tick and rotate into stick space (`steer.py`).
2. **Hurtbox timings are a hand-measured lookup table.** Any attack not among the 629 ids
   falls back to "hurtbox at 0.21s", so the bot dodges too early or too late against
   uncommon weapons, R2s and spells. *Fix:* pull exact attack-active frames from the
   game's own animation event data (TAE files in the dvdbnd archives), for every weapon.
3. **Pointers are resolved once and cached.** After a load or a new phantom joining,
   addresses go stale until the red-sign loop forces a re-read. *Fix:* re-resolve per
   tick (cheap) and treat unreadable chains as "no opponent".
4. **Hardcoded ranges.** Enemy range is fixed at 6 and player range at 2.5 for every weapon.
   `WeaponGhostHitTime` is tuned for a single weapon. *Fix:* look up range per
   `r_weapon` id from the weapon params / hitbox data.
5. **Tiny, personal training data.** The backstab net learned from ~18 KB of the author's own
   matches; the attack net was never finished. *Fix:* record your own duels with the
   same memory reader and retrain (or replace with a small modern model).
6. **Known gaps the author lists:** no poise awareness, trades too often, can't
   punish whiffed backstabs. Healing is broken and disabled (last commit).
7. **Engineering.** Global mutable state shared across threads with `volatile` flags,
   hardcoded `E:/...` paths (FANN crashes on long paths), blind sleep-based menu
   macros for auto red-signing. *Fix:* single-threaded fixed-rate loop (the nets are
   microseconds in numpy), config file, menu macros gated on memory state.

## Setup

```bash
python3 -m venv .venv && .venv/bin/pip install numpy evdev pillow
```

`/dev/uinput` must be writable by you (for example via a udev rule granting your user or the
`input` group access).

## Bring-up checklist (needs the game running)

1. **Controller slot:** Dark Souls only reads XInput slot 0, and Wine gives slots in
   connection order. If your real controller is connected first, the bot's pad lands
   in slot 1 and the game ignores it. Turn the real controller off (or
   `bluetoothctl disconnect <MAC>`) before starting the bot. Verified 2026-11-22.
2. Get into a duel (a second account/PC, or a friend through DSCM), then
   `python scripts/probe.py --watch`. HP, positions, animation ids and the timer should
   change as you move and attack. Any chain that shows `<unreadable>` needs re-finding.
3. Stand in an open spot, then run `python scripts/probe.py --calibrate-steering`.
4. In a duel: `python scripts/run_bot.py --dry-run` and check the printed decisions make
   sense (rolls when you swing, approach when far).
5. `python scripts/run_bot.py` and play normally: your controller is passed through
   the bot's pad. **Click L3 + R3 (both sticks, within 0.4 s of each other)** to let the bot fight; **touch
   anything** to take back over. It only engages player characters (never NPCs).
   On start it reconnects your Bluetooth controller behind the bot's pad; if it
   can't, press the Xbox button. Ctrl+C stops it (press the Xbox button again if
   your controller doesn't come back). `--bot-only` skips handoff.
   Verified in-game 2026-11-22: six handoffs each way, and it idled next to a friendly NPC.

### Auto red-sign (`--red-sign`)

Equip the Red Sign Soapstone as your **only** quick item (so "use item" can't use
anything else), stand somewhere safe at a dueling spot, run
`python scripts/run_bot.py --red-sign`, and hand over with L3+R3. While the bot has
control and is home with no opponent, it places a sign (confirming the use-item
animation started), re-places it every 4 minutes, and after each duel re-signs 8 s
after returning home. Being summoned is detected from your own character type
(2 = red phantom). As a red phantom it fights the host and the host's white phantoms;
it never engages NPCs, including hostile ones that wander up while it waits.
If use item does nothing (the game ignores it while your sign is already down), it
assumes the sign is still there and checks again in 4 minutes; it never gives up for good.
Verified live 2026-11-22: sign placed and seen in game (use-item confirmed in 0.13 s), then
summoned off it about an hour later and fought a full duel as a red phantom. A bug kept it from
re-signing after that duel; fixed the same day, but the re-sign after a duel hasn't been seen live yet.

**Arena mod (dugout + Traversal Trinket).** If the Traversal Trinket (goods 276) is the
second quick item, the bot handles the arena's dugout: after dying it reloads in the dugout,
switches to the trinket and uses it, walks to the arena centre, switches back to the
soapstone and signs. Positions live in `arena.json` (`dugout`, `center`; recorded in game).
The selected quick item can't be read from memory on this build, so the bot counts its own
d-pad presses: **start it with the soapstone selected** and don't cycle items while it drives.
If the trinket press doesn't get it out of the dugout, it cycles once and retries (3 tries).

**Greeting.** After being summoned it waits out the fade-in, locks on to the host and bows
(Back, then A: the Bow must be the selected gesture). A swing within reach cancels the
greeting. `--no-greet` turns it off. Gestures don't open while standing on your own summon
sign, which never happens once summoned.

**Unattended runs.** Start it as
`kde-inhibit --power --screenSaver .venv/bin/python scripts/run_bot.py --red-sign --start-as-bot`
so the screen doesn't lock and the PC doesn't sleep (either takes focus from the game, and
the game ignores the controller without focus). Leave the game window focused. Code changes
are picked up automatically between fights (hot reload); `--no-reload` disables that.

**Analysis.** `tools/backstab_report.py` lists every backstab attempt and whether it landed;
`tools/learn_hit_damage.py` rebuilds the per-attack damage/reach memory from recordings.

**Recordings.** Every tick with a real opponent present (bot or you driving) is saved to
`recordings/<date>-<time>.jsonl.gz`: both characters' raw memory values, subanimation
buckets, the controller output, and the bot's current routine. `--no-record` turns it off.
This is the training data for better nets (see weak point 5).

For an unattended run, `--start-as-bot` puts the bot in control from the start (touching
your controller still takes over).

The bot plays metal-crow's build assumptions by default (two-handing, swapping off
bare fists, fixed weapon ranges 2.5 / 6). Change them in `Config` in `ptde_ai/brain.py`.
